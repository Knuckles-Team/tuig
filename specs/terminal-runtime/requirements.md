# TUIG-RUNTIME requirements

## Native-only acceptance scope

The 2026-10-25 hard cut selects one Rust/Ratatui `tuig` executable. Python/Textual
source and test paths below are historical acceptance pointers, not maintained
implementations or proof for the native frontend. Preserve every product
requirement while porting its executable acceptance. Removal of Python binding
markers must remove their VERIFIED evidence from generated status. Historical
landing commits alone do not qualify native behavior. Existing native bindings
retain their explicitly bounded scope; full served parity stays open.


Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).
